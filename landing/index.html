CLI de site.bundle y design system

Comprueba y empaqueta sitios en el formato site.bundle, con tokens de diseño que puedes reutilizar.

Características

  • Determinista

    El mismo bundle produce el mismo archivo y los mismos hashes. Sirve para comparar versiones en CI.

  • Formato congelado

    site.bundle v1.0.0 no cambia de esquema sin una decisión explícita. Los códigos de error se mantienen.

  • Tokens con contraste

    Color en OKLCH, claro y oscuro, texto sobre fondo al menos 4.5:1 y bordes al menos 3:1.

  • Local

    La comprobación de esquema puede hacerse en el navegador, con un archivo que abres tú. No hay cuentas.

Funcionalidades

  • init

    Crea un site.bundle starter válido.

  • validate

    Comprueba esquema y reglas semánticas, y devuelve códigos estables.

  • normalize

    Ordena YAML y JSON para que el diff muestre cambios reales.

  • export

    Empaqueta el sitio en un .tar.gz reproducible.

  • integrity

    Calcula huellas SHA-256 por fichero y un hash global.

Roadmap

  1. Disponible

    CLI de bundles

    init, validate, normalize, export e integrity sobre site.bundle v1.0.0.

  2. Disponible

    Design system

    Hojas DTCG v1.0, variables CSS, contraste y showcase de tokens. La landing usa esas variables.

  3. Disponible

    Esquema en el navegador

    La vista Validar del showcase abre un bundle con la File API y lo comprueba con AJV. No necesita servidor. El export tar y la validación semántica siguen en la CLI.

  4. Fuera de alcance

    Sin VPS ni alojamiento

    webconfig no despliega sitios, no administra un VPS y no promete cuentas, colaboración ni publicación.

Empieza por la CLI

init, validate y export cubren el flujo. El design system es opt-in y no entra dentro del bundle.
